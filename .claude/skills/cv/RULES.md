# CV house rules

The single source of the rules both `/cv` procedures apply. The reader is the **gatekeeper**: a recruiter or their tool, matching a requirement list word for word.

## Positioning

- The title reads identically in header, summary and Focus areas, using the term recruiters search for.
- The summary supports the title.
- No length cap. Long Project lists are normal in the German freelance market; older Projects may be shorter.
- Page one stands alone: title, short profile, Focus areas, Industries, core tech, availability.

## Completeness per Project

Every Project has role, company, Industry, Period, Context (one to three sentences), Tasks, Outcomes, technologies.

- A missing Outcome is a finding.
- Everything actually done is listed, even small things.
- **Forgotten tasks** — for each Project, ask about anything on this list not covered: tests, CI/CD, deployment, monitoring, code review, mentoring or leading, stakeholder work, estimation, documentation, migrations, performance, security, accessibility.

## Tasks

- One concrete activity per bullet, named by what was done ("Migrated the build from Webpack to Vite"), so the gatekeeper can tick it off.
- English: past tense for finished Projects, present tense for the current one.
- German: noun style ("Migration von …").

## Outcomes

- Each Outcome names what changed.
- Numbers come only from the user or the repository; business impact only if the user states it.
- Filler no reader can verify ("in time & under budget", "100% kundenorientiert") is a finding: ask what actually changed.

## Tech line

- Spelled exactly as in `app/data/cv/tech.ts`, the only spelling authority.
- Every technology used in a Project is listed, including the obvious ones. Where an obvious tool is absent (Git platform, Jira, Scrum, CI tool), ask whether it was used.
- JavaScript, TypeScript, HTML and CSS appear on every Project where they were used; years per Skill are counted from the Projects that list them.
- Cross-check both directions: a technology named in Context or Tasks is in the list, and every listed technology is plausible for the Tasks.

## Languages

- German and English state the same facts, bullet for bullet.
- German reads as written in German, not translated.

## Attestation

- Every Task, technology, number and Outcome is attested by the user or the repository. Anything else is phrased as a question.
- All text is visible text.
- Keywords live in titles, Focus areas, Industries and technology lists; prose stays prose.
